  health returns a status-msg envelope; generic 200 payloads are free-form
  objects per =generic-object-schema=.

* Design
** Layout (src/starintel_client/)
- =_errors.py=: =StarIntelClientError= base; =StarIntelApiError=
  (=status_code=, =msg=, =correlation_id=, =code=, optional =info=) built by
  =error_from_payload()= (tolerates non-JSON/missing fields);
  =ManifestError=; =UnknownOperationError=.
- =_correlation.py=: =new_correlation_id()= (time-ordered hex, charset-valid
  per server bounds) and =validate_correlation_id()= mirroring the server's
  1..128 / alnum + =-_.:= rule.
- =_manifest.py=: dataclasses =ManifestResponse=, =ManifestOperation=,
  =ClientManifest=; =parse_client_manifest()= strict parsing (unknown schema
  string, missing keys, bad method, non-object entries -> ManifestError);
  legacy-route rejection at parse time via a forbidden-path check on both
  =path= and =openapi_path= (no legacy literal appears under src/: the
  matcher compares normalized templates against parameterized patterns);
  =render_path()= substitutes =:name= placeholders with quoted values.
- =_openapi.py=: =OpenApiOperation=, =OpenApiDocument=;
  =parse_openapi_document()=; =cross_check()= verifies every manifest
  operation appears in the OpenAPI document (=openapi_path= + method +
  =operationId = client_name=) -> ManifestError on drift.
- =_transport.py=: =TransportResponse= (status, headers, content);
  =AsyncTransport= wraps =httpx.AsyncClient=, =SyncTransport= wraps
  =httpx.Client=; bounded default timeouts (connect 5s / read 30s / write
  30s / pool 5s), caller timeout clamped to <=120s; conservative retry:
  idempotent GETs only, on transport errors and 502/503/504, bounded
  attempts (2 retries, 50ms/200ms backoff), never on other statuses (4xx
  never retried); retry backoff injectable for hermetic tests.
- =_client.py=: =StarIntelClient= (sync facade) + =AsyncStarIntelClient=
  (async core); shared pure helpers for headers/request building/response
  parsing; =discover()= fetches + parses both registry documents, builds the
  operation table; =from_registry()= for preloaded payloads (hermetic);
  generic =call(operation_id, path_params, json)= is the manifest-driven
  dispatch (new server operations become callable automatically); typed
  convenience methods ONLY for the 16 currently-contracted operations;
  Bearer auth when =api_key= set; per-request =X-Correlation-ID=
  (generated once per logical request, reused across retries), echo captured
  from response header with body =correlation_id= fallback.
- =_models.py=: =UserMetadata=, =CredentialMetadata=, =LoginResult=,
  =CredentialSecret=, =UserStatus=, =CredentialStatus= dataclasses parsed
  from the contract-pinned response schemas; everything else stays =Any=.
** Rejected alternatives
- Hardcoded route table in the client -> violates AGENTS.md rule 1; the
  manifest is the single source of routes.
- Codegen (writing .py files from the manifest at build time) -> build-time
  magic, poor testability; runtime manifest-driven dispatch + thin typed
  wrappers is smaller and keeps discovery live.
- Retrying non-idempotent verbs -> duplicates credential/user mutations;
  rejected.
- Pydantic models -> extra dependency; stdlib dataclasses suffice (task 3).
** Acceptance criteria / gates
1. =pytest= green (hermetic; live tests skip without =STARINTEL_LIVE_TEST=1=).
2. =ruff check .= clean; =mypy= strict clean.
3. Anti-legacy regression test fails when any forbidden route literal
   appears under src/ (proven red with a temporary fixture file).
4. Typed methods exist exactly for the 16 currently-contracted operations;
   generic =call= covers future manifest additions without code changes.
5. Gates recorded via =prolog-verify observe= at the candidate HEAD.

* Adversarial review
- Retry/correlation interaction: retried attempt reuses the same
  =X-Correlation-ID= (one logical request = one correlation id) -> accepted.
- Compromised/misconfigured manifest steering the client at legacy routes:
  parse-time rejection kills the operation set before any request can be
  built -> accepted; generic =call= resolves operations only from the
  validated table.
- Bootstrap secret leakage: passed per-call as a header, never stored on the
  client; api_key stored but never logged (client performs no header/body
  logging at all) -> accepted.
- 204/no-content and non-JSON success bodies: =data=None= / raw bytes
  fallback without raising -> accepted.
- Error body missing/invalid JSON: =StarIntelApiError= built with
  msg fallback derived from status code, =code=None= -> accepted.
- Timeout policy: bounded constants, caller value clamped -> prevents
  unbounded hangs -> accepted.
- mypy strict on async+sync duplication: shared pure helpers carry the
  logic; both facades stay thin -> accepted.
- Manifest/openapi drift (operation present in one, absent/renamed in the
  other): cross-check raises -> accepted.
- Legacy literals in tests: the forbidden strings must exist somewhere to
  scan for; they are confined to =tests/test_no_legacy_routes.py= scanning
  src/ only, and the scan itself normalizes =:param=/={param}= so template
  variants cannot slip through -> accepted.
